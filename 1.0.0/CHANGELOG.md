# DC Ultimate Changelog

## [Unreleased]

### Added — 반고닉 식별
- **고닉/반고닉/유동닉 3분류**: `src/core/identity.js` 를 추가했습니다. 지금까지 코드는 "uid 가 있으면 고닉, IP 가 있으면 유동" 이라는 이분법으로만 서술돼 있었고 반고닉은 어디에도 없었습니다. 실제로 두 신분은 닉 아이콘 파일명(`fix_nik.gif` = 고닉, `nik.gif` = 반고닉)으로 갈리며, 캡처 픽스처의 작성자 52건에서 예외 없이 성립합니다 — 사용자가 눈으로 보던 "회색 딱지 옆 노란점"이 이 파일명 차이입니다. 아이콘을 읽을 수 없는 화면에서는 고닉으로 단정하지 않고 `unknown` 을 돌려줍니다.
- **작성자 식별 키를 한곳으로 모음**: `userKeyOf()` (`uid` > `ip` > `nick`) 를 `archive-db.js` 의 `authorKeyOf()` 와 활동 팝오버가 함께 씁니다. 반고닉도 계정 uid 를 가지므로, 닉네임이 `ㅇㅇ` 처럼 겹쳐도 검색·활동 집계는 이미 사람별로 갈립니다.
- **활동 팝오버에 신분 표시**: 머리글이 `반고닉 · uid guest1433` 처럼 나옵니다. uid 가 없는 키(`nick:`/`ip:`)로 조회할 때는 "여러 명의 기록이 섞일 수 있다"는 경고를 함께 띄웁니다 — 2옥텟까지만 공개되는 유동닉 IP 를 개인 기록으로 오해하지 않도록.
- 분석 근거는 `SEMI_FIXED_NICKNAME_ANALYSIS.md`, 회귀 테스트는 `tests/identity.test.js` 입니다.

### Added — 닉네임 규칙의 사정거리
- **`nick` 규칙이 몇 명에게 걸리는지 미리 보여줍니다**: 사이드패널에서 대상을 "닉네임"으로 두고 값을 입력하면, 아카이브 기록으로 그 닉네임을 쓰는 식별자 수를 세어 보여줍니다(`nicknameHolders()`). 2개 이상이면 등록 전에 확인을 받습니다. `ㅇㅇ` 이면 "식별자 10개 (계정 3개 · 유동닉 IP 7개)" 처럼 나옵니다. 세는 방식의 한계(고닉/반고닉은 아카이브만으로 가릴 수 없고, 유동닉 IP 개수는 사람 수가 아니며, 관측 범위 안의 하한값)는 함수 docstring에 적어뒀습니다.
- **규칙 대상 드롭다운의 `nick` 라벨을 고쳤습니다**: "닉네임(고닉)" 이라고 적혀 있었습니다. 고닉은 uid 이고 닉네임 매칭은 가장 약한 규칙인데 라벨이 정반대로 안내해, `ㅇㅇ` 같은 공용 닉네임에 규칙을 걸도록 유도하고 있었습니다. "닉네임 · 여러 명이 함께 걸릴 수 있음" 으로 바꿨습니다. 선택 순서(기본값 `nick`)는 그대로 뒀습니다.

### Fixed — 활동 팝오버의 IP 대역 경고
- **"같은 IP 대역에서 닉네임 N개 관측" 이 한 번도 뜨지 않던 문제**: 백그라운드가 대역을 `post.ip.startsWith(band + '.')` 로 비교했는데, 디시가 유동닉 IP 를 2옥텟까지만 공개하므로(`175.223`) `'175.223'.startsWith('175.223.')` 는 항상 거짓이었습니다. 기능이 있는 것처럼 보였을 뿐 결과가 늘 빈 배열이었습니다. 대역끼리 비교하도록 고치고, `suspiciousIpBands()` 와 중복됐던 대역 계산을 `ipBand()` 하나로 합쳤습니다. 2옥텟 입력에 대한 회귀 테스트를 남겼습니다.

### Fixed — 유저 메모 키
- **`ㅇㅇ` 메모가 아무도 가리키지 못했던 문제**: 유저 메모(`userNotes`)의 유일한 입력 경로가 설정 화면의 자유 입력창이어서, 저장된 키가 사람이 타이핑한 문자열 그대로였습니다. `ㅇㅇ` 이라고 넣으면 그 메모가 서로 무관한 반고닉 여럿과 유동닉 여럿을 동시에 가리켜 의미를 잃었습니다. 이제 입력을 `uid:`/`ip:`/`nick:` 정규화 키로 바꿔 저장하고, uid 가 아닌 약한 키에는 저장 전에 무엇이 함께 걸리는지 알립니다.
- 기존 메모는 `migrateLegacyKeys()` 가 한 번 정규화해 옮깁니다(멱등). 두 옛 키가 같은 키로 합쳐지면 `updatedAt` 이 늦은 쪽을 남깁니다. 목록에는 `ㅇㅇ · 반고닉 (uid:guest1433)` 처럼 마지막으로 관측된 닉네임과 신분을 함께 보여, 정규화 키만 보고 누구인지 못 알아보는 일이 없게 했습니다.

### Fixed — 확장 프로그램 아이콘
- **설치 시 `'icon.png' 이미지를 디코딩하지 못했습니다` 오류**: `manifest.json`의 `icons`·`action.default_icon` 여섯 칸이 모두 2048×2048 / 2.68MB 짜리 `assets/icons/icon.png` 하나를 가리켰고, 이 파일에는 IHDR 직후에 23,733바이트 사설 청크(`caBX`)가 들어 있었습니다. 크롬은 설치 시점에 manifest에 선언된 모든 이미지를 미리 디코딩하는데, 이 단계에서 거부되어 설치가 실패했습니다. 크기별 아이콘(`icon16.png` / `icon48.png` / `icon128.png`)을 만들어 각 칸이 알맞은 파일을 가리키도록 했습니다.
- **`icon16.png` / `icon48.png` / `icon128.png` 가 깨진 PNG였던 문제**: 세 파일 모두 70바이트에 IHDR 청크가 없어 어떤 디코더로도 열리지 않았습니다(`file` 판정: `data`). 원인은 생성 스크립트에 하드코딩된 base64 리터럴의 오타 한 글자(`…SU6EUgAA…`, 정상값은 `…SUhEUgAA…`)였습니다. 1×1 플레이스홀더를 만들던 `assets/icons/make.js` · `assets/icons/generate-icons.js`를 제거하고, 원본에서 실제 아이콘을 축소 생성하는 `scripts/generate-icons.mjs`(`npm run icons`, 외부 의존성 없음)로 대체했습니다.
- **알림 아이콘 용량**: `chrome.notifications.create`에 2.68MB 아이콘을 넘기던 `src/core/notifications/notification-manager.js`를 포함해 알림 3곳(키워드 알림, 자동 로그인)의 `iconUrl`을 `assets/icons/icon128.png`(11.6KB)로 통일했습니다.
- **확장자와 실제 형식이 다른 이미지**: `assets/icons/dc_ultimate_icon.png`는 실제로 JPEG였습니다. 미참조 원본 이미지들과 함께 `assets/icons/master/`로 옮기고 확장자를 바로잡았습니다. 패키지에 실리는 `assets/icons/` 용량은 3.2MB → 16KB가 되었습니다.

### Fixed — 페이지 레이아웃
- **좌우가 잘리는데 가로 스크롤이 안 되던 문제**: 광고 날개를 숨기는 주입 스타일에 `html, body { overflow-x: hidden !important }` 가 함께 들어 있었습니다. 디씨 목록은 `.dcwrap.width1160` — 가로 1160px 고정이라, 창이 그보다 좁으면 우측 사이드바가 스크롤 없이 잘려 나갔습니다. 콘텐츠 스크립트가 `document_idle` 에 실행되므로 로딩 직후 떠 있던 가로 스크롤바가 곧 사라지는 증상으로 나타났습니다. 오버플로 clamp 를 제거해 가로 스크롤을 되돌렸습니다.
- **창 폭에 맞춰 `body` 를 축소하던 해킹 제거**: `document.body.style.zoom = innerWidth / 1160` 을 설정 없이 무조건 적용하고 `resize` 리스너도 해제하지 않았습니다. `innerWidth` 가 세로 스크롤바 폭을 포함해 배율이 늘 조금 크고, 남는 몇 px 이 위 `overflow-x: hidden` 에 먹혀 조용히 잘렸습니다. 축소 대신 가로 스크롤로 동작합니다.
- **날개 광고 숨김 범위 확대**: 날개 배너는 `#ad_floating` 의 자식이 아니라 형제이고 클래스 이름이 페이지 종류별로 다릅니다(`ad_left_wing_list_top` 등). `#ad_floating` 과 `div[class*="_wing_"]` 를 함께 숨겨 목록 외 페이지에서도 걷어냅니다. 와일드카드는 `_wing_`(양쪽 밑줄)이어야 하며, `wing` 으로 하면 디씨의 `.following` 이 걸립니다.
- 레이아웃 보정 로직을 `src/content/page-layout.js` 로 분리하고 `tests/page-layout.test.js` 를 추가했습니다. 실제 페이지 fixture 로 날개 셀렉터가 맞는지 확인하고, `overflow-x` 규칙과 `body.style.zoom` 이 되살아나면 실패합니다.
- **접속 직후 가로 스크롤바가 떴다가 사라지던 문제**: 위 clamp 를 걷어낸 뒤에도 증상이 남아 있었습니다. 남은 원인은 날개 광고 숨김 자체였습니다. 날개 배너는 `position: absolute; left: 50%` 에 `margin-left` 가 −780px / +750px 이라 문서 폭을 약 2200px 까지 밀어냅니다. 콘텐츠 스크립트가 `document_idle` + 동적 `import()` 로 늦게 실행되므로 브라우저가 먼저 가로 스크롤바를 그리고, 주입이 끝나면서 폭이 디씨 고정 1160px 로 접혀 스크롤바가 사라졌습니다. 즉 깜빡임은 잔재가 아니라 이 기능이 늦게 착륙하는 소리였습니다.
  - 날개 숨김을 **`settings.hideAdWings` 옵션으로 강등하고 기본값을 OFF** 로 바꿨습니다. 기본 상태에서는 날개 광고가 보이고 디씨 원본의 가로 스크롤이 그대로 유지됩니다.
  - 설정 페이지 "읽기" 탭에 토글을 추가했고, 켜고 끄면 새로고침 없이 즉시 반영됩니다(`removeAdWingHideStyles()` 로 대칭 해제).

### Changed — 사이드패널 서비스 바 페이징 · 드래그 재정렬
- **타일이 패널 폭을 넘칠 때 접근할 방법이 없던 문제**: 8개 타일은 320px 패널에서 최소 폭으로도 약 418px 을 요구했고, `.sp-servicebar` 는 `overflow-x: auto` 뿐인데 스크롤바가 `scrollbar-width: none` 으로 숨겨져 있어 뒤쪽 타일이 있다는 사실 자체가 드러나지 않았습니다.
  - 타일을 **페이지 단위로 나누고 scroll-snap 으로 넘기도록** 바꿨습니다. 타일 크기는 62px 고정이고, 패널 폭에 맞춰 페이지당 개수만 `ResizeObserver` 로 다시 계산합니다(폭이 바뀌어도 개수가 같으면 재렌더하지 않음). 페이지가 2개 이상일 때만 하단에 점 인디케이터가 뜨고, 점을 눌러 이동할 수 있습니다.
  - 좌우 패딩은 스크롤 컨테이너가 아니라 각 페이지가 갖습니다. 컨테이너에 두면 `flex: 0 0 100%` 가 패딩을 뺀 폭으로 풀려 페이지 폭이 `clientWidth` 와 어긋나고, 페이지마다 패딩만큼 밀려 다음 페이지가 새어 보였습니다.
  - `scroll-behavior: smooth` 도 컨테이너에서 뺐습니다. 걸어 두면 재렌더 후 위치를 복원하는 `scrollLeft = n` 같은 즉시 이동이 애니메이션으로 새어 나갑니다. 부드럽게 넘겨야 하는 곳(점 클릭, 드래그 중 자동 넘김)에서만 `scrollTo` 에 직접 넘깁니다.
  - 키보드 좌우 화살표로도 타일 사이를 옮겨 다니며 페이지가 따라 넘어갑니다.
  - **휠/트랙패드로도 좌우로 넘어갑니다**(`createWheelPager`). 바는 한 줄이라 세로로 스크롤할 것이 없으므로 세로 휠도 가로 이동으로 받습니다. 크롬이 가로 전용 스크롤러에 세로 휠을 흘려 주기도 하지만 `scroll-snap: x mandatory` 컨테이너에서는 스냅에 붙잡혀 제자리로 돌아오므로, 스크롤을 흘리지 않고 목표 페이지로 `scrollTo` 합니다.
    - 델타를 누적해 40px 을 넘을 때 한 페이지만 넘기고 250ms 쿨다운을 둡니다 — 휠 한 노치의 관성이나 트랙패드의 자잘한 델타가 두세 페이지를 지나치지 않습니다. 방향이 바뀌거나 400ms 이상 쉬면 누적을 버립니다. `deltaMode` 가 줄/페이지 단위(파이어폭스·리눅스)로 와도 픽셀로 환산합니다.
    - 끝 페이지에서 더 굴리면 `preventDefault` 하지 않아 본문이 대신 스크롤됩니다. 재정렬(드래그) 중에는 동작하지 않습니다.
- **타일 순서를 드래그로 편집**할 수 있습니다(`src/ui/sidepanel/tile-reorder.js`). 순서는 `settings.spTileOrder` 에 저장되고, 기존 `storage:changed` → `config:updated` 버스를 타므로 열려 있는 다른 패널에도 자동 반영됩니다.
  - 같은 포인터를 세 동작이 공유하므로 **롱프레스(350ms)** 로 갈랐습니다. 짧게 탭 → 서비스 전환, 옆으로 밀기 → 페이지 스와이프, 길게 누른 뒤 이동 → 재정렬. 드래그로 끝난 제스처의 뒤따르는 `click` 은 한 번만 삼켜 서비스가 잘못 전환되지 않게 합니다.
  - 드래그 중에는 DOM 을 건드리지 않습니다. 잡은 타일은 `transform` 으로 손가락을 따라가고 비켜 줄 타일들만 한 칸씩 밀려, 어디에 들어갈지가 애니메이션으로 드러납니다. 실제 재배치는 손을 뗄 때 한 번만 일어나므로 시각적 점프가 없습니다.
  - 페이지 경계에서는 한 칸 옆이 다음/이전 페이지의 반대쪽 끝이므로, 그 타일만 한 페이지 폭만큼 되감아 실제로 가는 자리를 가리킵니다(`computeShifts`). 드래그한 채 바 좌우 끝 40px 에 300ms 머무르면 인접 페이지로 자동 전환돼 다른 페이지에도 놓을 수 있습니다.
  - `prefers-reduced-motion` 에서는 스크롤/트랜지션 애니메이션이 꺼집니다.
- 하드코딩돼 있던 타일 마크업을 `src/ui/sidepanel/service-tiles.js` 의 데이터 정의로 옮기고, 개별 `click` 리스너를 위임 리스너 하나로 바꿨습니다. 저장된 순서는 `normalizeTileOrder()` 로 정규화해 중복·없는 키를 걷어내고 새로 추가된 타일을 뒤에 붙이므로, 타일이 늘거나 줄어도 사용자의 저장본이 깨지지 않습니다.

## [2.0.3] - 2026-08-20

### Fixed — 브라우저가 응답 없음 상태로 멈추던 문제 (2.0.2 회귀)

2.0.2 에서 추가한 댓글 배지 재적용용 `MutationObserver` 가 **자기 자신이 만든 DOM 변경을
다시 감지해 무한히 도는 루프**를 만들었습니다. 본문 페이지에 들어가 댓글이 한 번 로드되면
그때부터 CPU 를 100% 물고 탭이 굳었습니다.

**루프의 구조** — 옵저버는 `.view_comment` 를 `{childList, subtree}` 로 감시했는데,
`apply()` 가 그 안에 DOM 을 씁니다.

1. `_mountToolbar()` 가 `apply()` 마다 툴바를 **remove + insertBefore** 로 다시 만듦 → childList 변경
2. 글쓴이 배지 `<span>` 삽입 → childList 변경
3. 옵저버가 위 변경을 감지 → 콜백 → `apply()` → 다시 1번

`_applyScheduled` 플래그는 **같은 마이크로태스크 배치 안의 재진입만** 막았습니다. 실제
순서는 `콜백 → 플래그 ON → 마이크로태스크에서 플래그 OFF → apply() → 새 변경 기록 →
새 콜백(플래그는 이미 OFF)` 이라 매번 통과했습니다. 게다가 `Promise.resolve().then()`
으로 미뤘기 때문에 루프가 **마이크로태스크 큐 안에서만** 돌아 타이머·렌더·입력 처리가
아예 실행되지 못했고, 그래서 탭이 느려지는 게 아니라 완전히 멈췄습니다.
재현: 외부 변경 **1건**이 `apply()` 를 **500회 이상** 호출하며 끝나지 않음.

**수정 — 서로 독립적인 두 겹으로 막았습니다.**

- **`apply()` 를 진짜 멱등하게** 만들었습니다. 정착 상태에서 DOM 쓰기가 **0건**이면 애초에
  되먹일 변경이 없습니다.
  - 툴바를 **한 번만 생성**합니다(`_ensureToolbar`). 디시가 댓글 영역을 갈아끼워 툴바가
    목록과 떨어졌을 때만 옮깁니다. 라벨·개수는 `_syncToolbar()` 가 **값이 다를 때만**
    갱신합니다(`textContent` 대입도 childList 변경이라 무조건 쓰면 기록이 쌓입니다).
  - 덤으로 **클릭 리스너 누수**도 사라졌습니다. 예전에는 `apply()` 마다 새 버튼에 리스너를
    붙였으므로, 한 번 누르면 쌓인 수만큼 토글돼 필터가 제멋대로 켜졌다 꺼졌습니다.
- **옵저버가 자기 변경을 무시**합니다.
  - `apply()` 동안 `_applying` 을 세워 재진입을 막고, `finally` 에서
    **`observer.takeRecords()` 로 이번에 우리가 만든 변경 기록을 폐기**한 뒤 플래그를 내립니다.
    이것이 없으면 apply() 가 끝난 직후 큐에 남은 기록이 콜백을 다시 깨웁니다.
  - `_isForeignMutation()` 으로 추가/삭제된 노드가 전부 우리 것(`.dcu-cmt-*`)인 변경은
    무시합니다.
  - 스케줄을 마이크로태스크 → **50ms 타이머 디바운스**로 바꿨습니다. 혹시 되먹임이
    남아도 이벤트 루프를 굶기지 않고, 디시의 렌더 배치를 한 번으로 모아 줍니다.
- 페이지가 바뀌면 옵저버를 **다시 붙입니다**(`onPageChange`). 예전에는 `this._observer` 가
  이미 있으면 조기 반환해서 지난 페이지의 댓글 영역을 계속 보고 있을 수 있었습니다.
  `onDisable` 은 대기 중인 타이머까지 정리합니다.

`apply()` 가 멱등해진 덕에 `content/index.js` 의 `applyListFeatures()` 가 DOM 변경마다
호출하는 경로도 다시 안전해졌습니다. 2.0.2 에서 `list.dataset.dcuTreeApplied` 멱등 가드를
없앤 것이 이 경로의 비용을 함께 키우고 있었습니다.

> 저장소 스키마는 바뀌지 않았습니다 — `CURRENT_SCHEMA_VERSION` 은 `2.0.2` 그대로입니다.

### Fixed — 키워드 알림 (Keyword Alerts)
- **배경 스캔이 항상 0건이던 문제**: 서비스 워커에는 `DOMParser`가 없어 `ArticleParser`가 언제나 빈 목록을 반환했습니다. DOM 없이 동작하는 `src/core/keyword-alert/list-page-parser.js`를 추가해 백그라운드에서도 갤러리 목록을 파싱합니다. (공지 행은 제외)
- **마이너/미니 갤러리 URL 오류**: `mgallery` / `mini` 타입이 `major`로 처리되어 잘못된 목록을 조회했습니다. `normalizeGalleryType()`을 도입해 사이드패널 검색(`QueryBuilder`)과 알림 스캔이 동일한 규칙을 사용합니다.
- **데스크톱 알림이 뜨지 않던 문제**: 존재하지 않는 아이콘 경로(`icons/icon128.png`)로 `chrome.notifications.create`가 실패했습니다. `chrome.runtime.getURL()` 기반 절대 경로로 교체하고 실패 시 로그를 남깁니다.
- **알람이 영원히 발화하지 않던 문제**: 서비스 워커가 깨어날 때마다 알람을 전부 지우고 다시 만들어 주기가 초기화됐습니다. `initAlarms()`가 멱등적으로 동작하도록 변경했습니다.
- **콜드 스타트 경합**: 메시지 핸들러가 비동기 초기화 이후에 등록되어, 사이드패널의 첫 요청이 핸들러를 찾지 못했습니다. 핸들러를 동기 등록하고 각 핸들러가 초기화 완료를 기다리도록 했습니다.
- **사이드패널에서 알림 추가가 동작하지 않던 문제**: 사이드패널은 `window.prompt()` / `confirm()` / `alert()` 대화상자를 표시하지 않습니다. 인라인 등록 폼, 2단계 삭제 확인, 인라인 상태/오류 메시지로 교체했습니다.
